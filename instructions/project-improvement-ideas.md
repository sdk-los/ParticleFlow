# Идеи функций и улучшений для проекта

## 1. Новые функции

### 1.1. Пресеты настроек — реализовано

Добавить готовые наборы параметров для разных визуальных режимов:

| Пресет | Описание |
|---|---|
| `Calm` | Медленные частицы, слабое свечение, небольшой радиус притяжения |
| `Neon` | Яркое свечение, высокая насыщенность, больше частиц |
| `Storm` | Быстрое движение, сильное притяжение, активная пульсация |
| `Minimal` | Мало частиц, без пульсации, мягкий фон |

Пользователь сможет быстро менять настроение сцены без ручной настройки каждого слайдера.

Реализовано: в панели настроек добавлены пресеты `Calm`, `Neon`, `Storm` и `Minimal`. Каждый пресет применяет набор параметров частиц, скорости, свечения, палитры, притяжения, пульсации и поведения на границах, синхронизирует значения контролов и сохраняет итоговые настройки в `localStorage`.

### 1.2. Сохранение настроек — реализовано

Сохранять текущие параметры в `localStorage`, чтобы после перезагрузки страницы пользователь видел тот же режим:

- количество частиц;
- размер частиц;
- скорость;
- оттенок;
- сила и радиус взаимодействия;
- включение пульсации;
- режим отражения от границ.

Реализовано: значения сохраняются в `localStorage` при изменении контролов и загружаются при открытии страницы.

### 1.3. Несколько режимов взаимодействия с курсором — реализовано

Сейчас частицы притягиваются к курсору. Можно добавить переключатель режима:

| Режим | Поведение |
|---|---|
| Притяжение | Частицы летят к курсору |
| Отталкивание | Частицы разбегаются от курсора |
| Орбита | Частицы закручиваются вокруг курсора |
| След | Курсор оставляет временный светящийся след |

Это сделает проект более интерактивным и даст больше визуальных вариантов.

Реализовано: в панели настроек добавлен выбор режима курсора `Притяжение`, `Отталкивание`, `Орбита` и `След`. Режим сохраняется в `localStorage`, участвует в пресетах, синхронизируется при сбросе и загрузке настроек. Для частиц добавлена отдельная логика притяжения, отталкивания и орбитального движения, а режим `След` рисует за курсором временные светящиеся точки с затуханием.

### 1.4. Выбор цветовой палитры — реализовано

Вместо одного `hue` можно добавить палитры:

- монохромная;
- холодная;
- тёплая;
- неоновая;
- радужная;
- пользовательская через два или три цвета.

В коде это можно реализовать через функцию, которая назначает частицам цвет в зависимости от выбранного режима.

Реализовано: в панели настроек добавлен выбор палитры `Монохромная`, `Холодная`, `Тёплая`, `Неоновая`, `Радужная` и `Пользовательская`. Для пользовательского режима доступны три цвета, выбранная палитра сохраняется в `localStorage`, а частицы получают цвета через отдельную функцию назначения палитры.

### 1.5. Управление фоном — реализовано

Добавить настройки фона:

- выбор цвета фона;
- мягкий градиент;
- прозрачный фон для записи видео;
- затемнение или усиление контраста.

Это особенно полезно, если эффект будет использоваться как фон для лендинга, заставки или демо-страницы.

Реализовано: в панель настроек добавлены режим фона, выбор цвета, интенсивность градиента и прозрачный режим. Пресеты теперь меняют фон сцены вместе с параметрами частиц.

### 1.6. Генерация частиц по клику

Добавить реакцию на клик или тап:

- вспышка частиц в точке клика;
- временное увеличение скорости;
- круговая ударная волна;
- создание новых частиц на несколько секунд.

На мобильных устройствах это может заменить часть mouse-эффектов.

### 1.7. Экспорт изображения

Добавить кнопку сохранения текущего кадра:

- `Скачать PNG`;
- `Скопировать изображение`;
- `Сохранить пресет`.

Для PNG можно использовать `canvas.toDataURL()` или `canvas.toBlob()`.

### 1.8. Отображение FPS — реализовано

Добавить небольшой переключатель `Показывать FPS`.

Это поможет понять, какие настройки слишком тяжёлые для устройства, и будет полезно при оптимизации.

Реализовано: в панель настроек добавлен переключатель `Показывать FPS`, значение сохраняется в `localStorage`. При включении поверх canvas появляется компактный индикатор, который обновляет средний FPS примерно раз в полсекунды.

## 2. Улучшения интерфейса

### 2.1. Группировка настроек — реализовано

Панель настроек разделена на логические блоки:

- `Быстрый старт` с пресетами;
- `Частицы`;
- `Движение`;
- `Курсор`;
- `Цвет`;
- `Производительность`.

Теперь связанные параметры находятся рядом, а интерфейс становится проще и понятнее.

### 2.2. Кнопка сброса настроек — реализовано

Добавить кнопку `Сбросить настройки`, которая:

- возвращает значения `config` по умолчанию;
- обновляет значения слайдеров;
- обновляет подписи рядом со слайдерами;
- пересоздаёт частицы при необходимости.

Реализовано: кнопка сбрасывает `config` к значениям по умолчанию, очищает сохранённые настройки, синхронизирует контролы и пересоздаёт частицы.

### 2.3. Улучшение мобильного опыта - частично реализовано

Сейчас проект ориентирован на курсор мыши. Для мобильных устройств стоит добавить:

- обработку `touchmove` — реализовано;
- реакцию на `touchstart` — реализовано;
- более узкую панель настроек на маленьких экранах;
- закрытие панели свайпом вправо;
- увеличенные области нажатия для кнопок и переключателей.

Реализовано: `touchstart` и `touchmove` обновляют позицию притяжения частиц по первому активному касанию, `touchend` и `touchcancel` убирают точку взаимодействия за пределы canvas, а для canvas задано `touch-action: none`.

### 2.4. Доступность

Можно улучшить доступность интерфейса:

- добавить `aria-label` для кнопок открытия и закрытия панели;
- добавить `aria-hidden` для декоративного canvas, если он не несёт смысловой нагрузки;
- управлять фокусом при открытии и закрытии панели;
- закрывать панель не только через `Escape`, но и корректно возвращать фокус на кнопку настроек.

### 2.5. Визуальные подсказки

Для сложных параметров можно добавить короткие подсказки:

- что делает `Сила взаимодействия`;
- чем отличается отражение от переноса через границы;
- как влияет `ShadowBlur` на производительность.

Подсказки лучше сделать ненавязчивыми: через `title`, tooltip или маленькую иконку рядом с названием настройки.

## 3. Технические улучшения

### 3.1. Поддержка `devicePixelRatio` — реализовано

Реализовано: canvas хранит размеры сцены в CSS-пикселях, а реальные `canvas.width` и `canvas.height` масштабируются через `window.devicePixelRatio`.

Контекст масштабируется через `ctx.setTransform(...)`, поэтому координаты частиц, курсора, радиусов и границ остаются в CSS-пикселях, а изображение на Retina-экранах становится чётче.

### 3.2. Ограничение тяжёлых настроек

Некоторые комбинации могут просаживать FPS:

- много частиц;
- высокий `shadowBlur`;
- большой радиус взаимодействия;
- высокая скорость.

Можно добавить адаптивное ограничение: если FPS падает ниже заданного уровня, автоматически уменьшать количество частиц или свечение.

### 3.3. Пауза при скрытой вкладке — реализовано

Добавить обработчик `visibilitychange`:

- когда вкладка скрыта, останавливать `requestAnimationFrame`;
- когда вкладка снова активна, запускать анимацию.

Это снизит нагрузку на CPU и батарею.

Реализовано: цикл анимации вынесен в `startAnimation()` и `stopAnimation()`. При скрытии вкладки текущий `requestAnimationFrame` отменяется, при возвращении вкладки анимация запускается заново, а счётчик FPS сбрасывается, чтобы не показывать скачки после паузы.

### 3.4. Разделение кода на модули

Если проект будет расти, `js/script.js` можно разделить:

- `particle.js` — класс частицы;
- `config.js` — значения по умолчанию и константы;
- `controls.js` — панель настроек;
- `canvas.js` — размер canvas и цикл анимации;
- `storage.js` — сохранение и загрузка настроек.

Для текущего размера проекта один файл допустим, но модульность поможет при добавлении новых режимов.

### 3.5. Уменьшение количества вычислений в кадре

В каждом кадре для каждой частицы считается расстояние до курсора через `Math.sqrt`. Для большого количества частиц это может быть дорого.

Оптимизация:

- сравнивать квадрат расстояния с квадратом радиуса;
- вызывать `Math.sqrt` только для частиц внутри зоны притяжения;
- пропускать расчёты притяжения, если курсор вне canvas.

### 3.6. Единый объект значений по умолчанию

Сейчас значения по умолчанию есть и в HTML, и в `config`. Лучше хранить их в одном месте:

- либо генерировать контролы из JavaScript;
- либо при инициализации синхронизировать HTML с `config`;
- либо вынести настройки в отдельную структуру с `min`, `max`, `step`, `label`, `defaultValue`.

Это уменьшит риск, что значение в HTML и значение в JS разойдутся.
